CAMS Theme Refactor Audit
=========================

Generated during the hybrid red-blue theme refactor.

Last updated after the Phase A/B migration pass, expanded Phase C adoption, and the latest shell/shared/settings/hub cleanup pass.

Theme rules for future work are documented in `docs/theme_guidelines.md`.

Refactor Targets
----------------

- Canonical theme files: `lib/core/constants/app_colors.dart`, `lib/core/theme/app_theme.dart`, `lib/core/theme/cams_theme_tokens.dart`.
- Shared UI migration now covers main shell bottom nav, core bottom sheets, song list tile, skeleton placeholders, mini player, schedule palette, CAMS button/card/logo/glow effects, theme toggle, app drawer, and Play to Space sheet.
- Space control migration now covers offline tab, offline library bottom sheet, mood display, sensor data, space detail, and space settings palettes.
- High-traffic migration continued for Library, Home, and Now Playing local palettes. Library status/action colors now use semantic tokens; Home's mode-control card now uses `textOnAccent`; Now Playing fallback/sheet/mood colors now use tokens. Remaining Home/Now Playing hits are fixed black/white artwork contrast overlays.
- Search, Welcome, Store Selection, and Space Schedule page-level UI colors have been routed through `ColorScheme`/`CamsThemeTokens` where they were static theme colors.
- Additional feature cleanup now covers Home drawer, legacy Login page, Login v2 hard colors, Forgot Password, Fuzzy Override editor sheet, Space Device page, Space Hub palette, Context Rules page, Create Rule page, API playlist detail, Search artist/album/playlist/category detail fallbacks, Settings pages, Full Screen Player, Space Management Tile, Space Settings sheet palette, Store Dashboard sheet/avatar UI, Rules placeholder, and offline mood gradients.
- Brand/platform sync includes `assets/images/cams_logo.svg`, `assets/generate_logo.dart`, `web/manifest.json`, and native splash comments in `pubspec.yaml`.

Allowed Color Categories
------------------------

- `Colors.transparent`.
- Dynamic content colors parsed from API/user/music hex fields.
- Test fixtures and mock data that intentionally exercise arbitrary colors.
- Central token definitions in `AppColors` and `CamsThemeTokens`.
- Generated asset colors in the logo source, as long as they match the hybrid brand palette.

Follow-Up Cleanup Rules
-----------------------

- Prefer `Theme.of(context).colorScheme` for Material roles.
- Prefer `context.camsTokens` for app-specific roles: sidebar, elevated surfaces, alert backgrounds, slider tracks, mood colors, and tech accent.
- Avoid adding new raw `Color(0x...)` or `Colors.white/black/grey/red/blue/orange/green` in feature widgets unless it is content-driven or explicitly allowlisted.
